# コスト最適化設計
### ECSタスク数とリソースのサイジング
- アプリケーションの稼働に必要十分なリソース量を見定めること

### CPUアーキテクチャ
- GravitonベースのFargateを活用
- x86ベースのプロセッサと比較すると、約20%低いコストで同等以上のパフォーマンスを発揮する
- ※ 注意点としてARM64bitに対応しているコンテナイメージである必要がある
  - コンパイルが必要なアプリケーションではターゲットアーキテクチャを指定する必要あり
  - ライブラリなどがバイナリ形式で提供されている場合、そのバイナリもARM64bitに対応している必要がある

### Compute Savings Plans
 - 1年、3年いずれかの期間で指定リソースの利用を事前コミットすることで大幅に割引される
 - コミットしたリソース使用量を超過した分のの料金は通常料金が適用される

### 環境別におけるコスト最適化
以下3項目は環境に応じてコスト最適化構成を検討する余地がある
- ECSタスク稼働時間帯別の調整
- CloudWatch Container Insightsの有効・無効
- GuardDuty ECS Runtime Monitoringの有効・無効

### Fargate Spotの活用
- オンデマンドと比較して7割引きの料金で利用することが可能
- 以下2点の考慮事項が発生
  - キャパシティプロバイダー戦略の設定が必須(オンデマンドとSpotの比率を決める設定)
  - 終了通知に対する考慮 ⇒ ECSタスクが終了する2分前にEventbridgeにてECSタスクへの状態変更がイベント通知される
 
### ECRコンテナイメージのメンテナンス
- ライフサイクルによって不要となったコンテナイメージを削除する
- コンプライアンス要件などで大量のイメージを長期保存する必要がある場合、ECRアーカイブストレージクラスの活用も有効
