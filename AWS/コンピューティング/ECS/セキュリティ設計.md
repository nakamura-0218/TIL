# セキュリティ対策
## コンテナイメージに対する対策
### イメージスキャン機能
- ECR 基本スキャン
  - 無料で利用可能
  - ECRにイメージプッシュ時にスキャンや手動スキャンが可能
 
- ECR 拡張スキャン(継続的なスキャンが可能なため推奨)
  - 内部的にInspectorと統合されている
  - スキャン毎に料金が発生
  - 一定期間毎における継続的な自動スキャンに対応
  - 基本スキャンと比べてサポートされているOSベースイメージの種類が豊富且つ、言語パッケージの脆弱性スキャンにも対応している
  - InspectorはSecurity Hub CSPMと統合可能のため、発出イベントをEventbridgeで抽出し、SNSとQ Developer in chat applicationsを経由させることで、slackに通知することが可能

 - Trivy(OSS)
   - サポート対象のOSが上記のECRスキャンより多様且つ、複数の言語をサポートしている
   - IaCやKubernetesのマニフェストに対するセキュリティチェックも可能
   - 実行方法がシンプルのためCI/CDパイプラインに組み込みやすい
   - Security Hub CSPMとの統合をサポート

### Dockerfileの設定不具合検出
- docker buildx buildコマンドに「check」オプションを付与
  - Docker社が提供するベストプラクティスに沿ったチェックを実行
  - イメージの事前ビルドは不要で、Dockerfileの不備を検出
 
- Dockle(OSS)
  - 事前にビルドイメージが必要
  - 上記のdocker buildx buildコマンドのcheckオプションより多くの検証観点が含まれており、コンテナイメージに対して網羅的にセキュリティチェックが実現可能
 
- Hadolint(OSS)
  - ShellCheckに基づく解析が可能で、RUNコマンドなどのシェル構文の記述に対して、セキュリティ観点で解析をサポート可能

### 埋め込まれたマルウェアの対策
- Docker HubやECR Public Galleryからイメージを取得する場合は、認定バッチ等が添えられている信頼できるものを利用
- ECS上のアプリケーションに対する振る舞いに特化したGuardDuty(GuardDuty ECS Runtime Monitoring)はマルウェアに対する検知の対策として有効

## レジストリに対する対策
### ECR考慮事項
- 過去バージョンの管理は切り戻しがしやすくなる反面、時間の経過とともに脆弱性を含むバージョンへと変容していくため、必要十分なバージョンを保持しつつも、不要なバージョンはECRのライフサイクルポリシーによって削除することによって、セキュリティ観点・コスト観点において有効
- 不正なイメージの混入や、誤ってECSタスクが参照しているコンテナイメージを削除してしまわないように、IMMUTABLE設定を検討
